# v3 — Data-Center IoT Sensor Network (DAD dataset)

The project's **third domain**. Same architecture as v1 (preprocess → analyse → detect → reason →
query engine → interface → verified LLM explanation), applied to a **data-center IoT/MQTT network**
with **real, labelled anomalies**.

> **Core principle (shared with v1/v2):** computation = code (the truth); the LLM only explains, and a
> faithfulness check verifies it invents no numbers.

**New here? Start with [GETTING_STARTED.md](GETTING_STARTED.md).**

## Web UI — how to run & what it does
```bash
python3.12 apps/web/app.py            # starts the server, prints e.g. http://localhost:3040
# python3.12 apps/web/app.py 8080     # force a port  (or:  PORT=8080 python3.12 apps/web/app.py)
```
Open the printed URL. **What it is:** a small browser **chat** over the same `interface` module — a
Flask backend (`apps/web/app.py`) serving one static page (`apps/web/index.html`, plain HTML+JS, no
build step). **What it does:**
- **Ask in plain English** — type a question or click an **example chip** ("How many attacks on
  Wednesday?", "Which IP is the attacker?", "Highest temperature on Friday?").
- Each question is POSTed to `/api/ask`, which routes it through the deterministic **query engine**;
  **every number is computed by code**, and the reply shows trust labels — 🔢 *computed*, 📚 *context*,
  🧠 *inferred*.
- If a local **Ollama** model is running, answers are reworded into friendlier prose, **gated by a
  faithfulness check** that rejects any invented number/IP; with no Ollama it shows the exact template
  (the `used_llm` flag reflects which). The port defaults to **3040** and falls back to the next free
  port if busy. Stop with `Ctrl-C`.

## Headline result
On the **real** attack labels, the per-type table proves the two channels are complementary (flow: 0.00
recall on *modification*, 1.00 on *duplication*; value the opposite), and shows honestly that fusion
trades precision for recall and does **not** beat the stronger single channel when the other is weak.
Full table + reasoning in [`report/EVALUATION.md`](report/EVALUATION.md).

## Dataset — DAD (real, verified)
Vigoya, Fernández, Carneiro & Cacheda (2020), *"Annotated Dataset for Anomaly Detection in a Data
Center with IoT Sensors"*, *Sensors* 20(13), 3745 — <https://github.com/dad-repository/dad>.

7 days of MQTT network capture (`.pcap`) + per-packet attack labels. **544 real labelled attack
packets** (duplication / interception / modification), attacker IP `10.6.56.41`. The temperature
readings live inside the MQTT payloads (parsed with `scapy`). Verified: per-day attack counts match
the paper's schedule (see `docs/PLAN.md`). **Its key advantage over v1: real anomaly labels** — v1 had
only synthetic ones.
